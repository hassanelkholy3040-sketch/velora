# VELORA

VELORA is a bilingual fashion storefront demonstration built with React and Vite. It provides a client-side shopping experience for browsing a small, locally defined catalog, selecting product variants, managing a cart and wishlist, and trying a simulated checkout.

## Overview

This project is a front-end prototype. Product information and translations are bundled with the application. Cart, wishlist, and language preferences are stored in the browser. Checkout demonstrates form validation and an order confirmation screen; it does not connect to a commerce service.

## Features

- **English and Arabic interface:** Switch languages in the header. The page updates its language and direction attributes for left-to-right English and right-to-left Arabic layouts.
- **Product catalog:** Browse 16 catalog entries for men and women, including product images, descriptions, available sizes and colors, stock counts, and sale information.
- **Search and filters:** Search product names, descriptions, categories, and colors in English or Arabic. Filter by category, gender, size, color, price range, and sale status.
- **Sorting:** Sort catalog results by featured order, newest, price ascending or descending, and name.
- **Product details:** View product descriptions and image galleries, select a size and color, change quantity within available stock, and browse related products.
- **Cart:** Keep separate lines for different product variants, change quantities, remove items, and review calculated totals.
- **Wishlist:** Save and remove products from a wishlist.
- **Browser storage:** Language, cart, and wishlist are persisted in `localStorage`. The latest demo order summary is held in `sessionStorage`.
- **Demo checkout:** Validate contact and shipping form fields and show a simulated order confirmation.
- **Responsive interface:** The layout includes mobile navigation and a mobile filter drawer.

## Technologies

- React and React DOM

## Prerequisites

- Node.js **20.19 or newer** in the 20.x line, or **22.12 or newer**. This matches the installed Vite 7 package's engine requirement.
- npm, which is included with Node.js.

Check your installed versions with:

```sh
node --version
npm --version
```

## Installation and development

From the project root, install dependencies and start Vite:

```sh
npm install
npm run dev
```

Open the local address printed by Vite in your browser (by default, `http://localhost:5173`).

## Available commands

These commands are defined in `package.json`:

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the Vite development server. |
| `npm run build` | Create the production build in `dist/`. |
| `npm run preview` | Serve the existing production build locally; run `npm run build` first. |

## Product data and translations

The catalog is defined in `src/data/products.js` and exported as a local JavaScript data set. Each product includes English and Arabic names and descriptions, category labels, sizes, colors, image URLs, prices, collection flags, and a stock count. The same file defines the shipping threshold and standard shipping charge.

Interface strings are kept in `src/translations/index.js` under the `en` and `ar` language keys. The application selects the active language in the shared store and updates the document's `lang` and `dir` attributes when the language changes. Product copy uses the bilingual fields in the catalog.

## Cart and shipping

Cart lines identify a product variant by product, size, and color. Cart calculations use the current catalog prices and quantities. The configured rules are:

- An empty cart has no shipping charge.
- A non-empty order with a subtotal below **$100 USD** has **$8 USD** shipping.
- A subtotal of **$100 USD or more** qualifies for free shipping.

These values are defined by `SHIPPING_THRESHOLD` and `SHIPPING_COST` in `src/data/products.js`.

## Checkout and data boundaries

Checkout is a front-end demonstration. It validates the form in the browser and displays a confirmation using a locally generated demo reference. It does not process payments, contact a payment provider, send an order to a server, or create a real server-side order. The demo order summary is stored in the current browser session; it is not an order-management system.

## Build and deployment

Build the static site with:

```sh
npm run build
```

The deployable files are written to `dist/`. For Netlify, publish `dist/`; `public/_redirects` provides the single-page-app fallback by routing requests to `/index.html`. Other static hosting providers must be configured to serve the app entry point for client-side routes as well.

To inspect a production build locally:

```sh
npm run preview
```

## Known limitations

- The product catalog is static and bundled with the front end; there is no product API, database, account system, or live inventory service.
- Cart and wishlist data are local to the browser's `localStorage`; they are not synchronized across devices or accounts. The demo order summary uses `sessionStorage`.
- No real payment, order processing, email delivery, or newsletter subscription is implemented. Newsletter feedback is local to the interface.
- Product photography and web fonts are loaded from external services, so those assets require network access. Product images have an in-app fallback if an image cannot be loaded.
- A static host needs the client-side route fallback described above for direct links to nested routes.
